# ドキュメント

TimeCard の利用方法、要件、設計、開発、運用に関する文書の入口です。

同じ情報を複数の文書で独立に定義せず、最も自然な責務を持つ文書を Source of Truth とします。コード、contracts、DB schema、migration、テストコードから直接確認できる詳細は、それらを Source of Truth とし、文書へ重複して記載しません。

## 文書一覧

| 文書                                                      | 責務                                                                                         |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| [用語集](./用語集.md)                                     | 業務用語の意味と分類                                                                         |
| [要件定義書](./要件定義書.md)                             | 業務ルール、外部から観測可能な振る舞い、制約、非機能要件                                     |
| [設計書](./設計書.md)                                     | 要求を実現するアーキテクチャ、責務境界、依存方向、主要処理方式、データ設計                   |
| [設計判断記録（ADR）](./adr/README.md)                    | 長期的に残す価値がある重要な設計判断と、その背景・選択肢・結果                               |
| [CONTRIBUTING](../CONTRIBUTING.md)                        | 開発環境、branch、validation、migration、commit、Issue、ドキュメント更新のルール             |
| [開発標準](./開発標準.md)                                 | 変更単位、計画、テスト戦略・分類・保証責務、検証、順序依存の挙動、利用者向け成果物の品質確認 |
| [環境構築・デプロイ手順書](./環境構築・デプロイ手順書.md) | 環境構築、外部サービス設定、DB migration、deployment、本番 DB backup・復旧の安全条件         |
| [利用者ガイド](../apps/help/content/docs/index.mdx)       | スタッフ・管理者が目的の操作を完了するための操作方法                                         |
