# AI エージェントによる計画

本システムの変更要求または粗い実装案から、実行可能な実装計画を定義する。

この workflow の責務は計画の確定までであり、ファイル変更や commit は行わない。

## 入力

要求、Issue、または人が作成した粗い実装案を入力とする。

人がタスク境界、順序、対象外、実装方針を明示している場合は、それらを現在の要求として扱う。現在の repository state と両立しない場合は、黙って別の計画へ置き換えず不整合を明示する。

## 計画の契約

実装計画は、実装担当が追加の大きな仕様判断・設計判断・Scope 判断をせず着手できる状態でなければならない。そのために `AGENTS.md`、`CONTRIBUTING.md`、変更に関係する code / tests / docs を必要な範囲で確認する。

Run / Task の関心事と分割原則は [開発標準](../開発標準.md) に従う。

Task の計画に含める内容は [開発標準](../開発標準.md) に従う。

ファイル名、symbol、型名などは実装に必要で repository から確定できる場合だけ含める。固定テンプレートを満たすための情報は追加しない。

計画を詳細化するためだけに実装を先行せず、判断に不要な広範囲調査も行わない。

## 完了条件

次が成立している計画を「実行可能」とする。

- Run の関心事と Scope が一意に説明できる
- 実装担当へ委ねてはいけない重要な仕様・設計判断が残っていない
- 各 Task の目的と完了状態が区別できる
- 必要な Task 間依存だけが順序として表現されている
- 主要な validation と文書更新責務が欠落していない

ユーザー判断や再計画が必要な未確定事項が残る場合は、実行可能な計画として扱わない。

## 出力

実行可能な Task と、それぞれの目的、変更後の状態、必要な変更、validation、必要な前提関係を示す。

この workflow 単独では計画を出力した状態で責務を完了する。確定済み計画の実行は [実行 workflow](./execute.md) の責務とする。
