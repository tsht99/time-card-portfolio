# 用語集

## 1. 文書の役割

本書は、本システムで使用する業務用語の意味を定義する。

各用語は、その概念を所有する境界づけられたコンテキストに対応する「分類」で整理する。会話、Issue、要求・設計文書、UI、コードでは、同じ業務概念を原則として同じ用語で表す。

本書は詳細な業務ルールや実装仕様を複製しない。具体的な振る舞い・制約は [要件定義書](./要件定義書.md)、責務境界・処理方式は [設計書](./設計書.md)、設計判断の背景は [ADR](./adr/) を Source of Truth とする。

## 2. 用語

分類の設計上の位置づけは [設計書](./設計書.md) を参照する。

| 用語         | 分類         | 説明                                                                                                                                                                                                                                                                                 |
| ------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 利用者       | アクセス管理 | 本システムに登録される人。スタッフと管理者を含む。                                                                                                                                                                                                                                   |
| 役割         | アクセス管理 | 利用者に割り当てる区分。スタッフ（`staff`）と管理者（`admin`）を区別する。利用状態や、個別操作に対する具体的な変更権限とは別の概念として扱う。                                                                                                                                       |
| スタッフ     | アクセス管理 | 役割が `staff` の利用者。出勤・退勤、自身の勤怠確認など、スタッフ向けの操作を行う。利用可否は利用状態によって管理する。                                                                                                                                                              |
| 管理者       | アクセス管理 | 役割が `admin` の利用者。ユーザー管理、勤怠管理、時給管理、給与見込みの確認など、管理者向けの操作を行う。                                                                                                                                                                            |
| 表示名       | アクセス管理 | システム上で利用者を識別するための業務用名称。初回登録時には LINE の表示名を初期値として利用できるが、その後は LINE のプロフィール表示名とは独立して扱う。                                                                                                                           |
| 本人確認     | アクセス管理 | LINE の認証情報によって、アクセスしている人の本人性を確認すること。本人確認の成功は、本システムの利用許可を意味しない。承認待ちのスタッフは本人確認に成功しても利用を開始できない。                                                                                                  |
| 利用状態     | アクセス管理 | スタッフが本システムを利用できる状態を表す区分。本人確認後に利用承認を待つ「承認待ち」（`pending`）、利用が許可された「利用中」（`active`）、継続利用を許可しない「利用停止」（`inactive`）を区別する。役割とは別の概念として扱う。                                                  |
| 利用承認     | アクセス管理 | 承認待ちのスタッフを利用中へ変更し、本システムの利用を許可すること。                                                                                                                                                                                                                 |
| 勤怠         | 勤怠管理     | 一回の勤務について、出勤日時、退勤日時、勤務日、勤務区分などを記録する単位。同じ利用者・同じ勤務日・同じ勤務区分であっても、別の勤務であれば複数の勤怠が存在できる。                                                                                                                 |
| 勤務日       | 勤怠管理     | 勤怠を日単位で扱うための基準日。出勤日時の日本時間（Asia/Tokyo）の日付から決定し、独立した入力値として扱わない。                                                                                                                                                                     |
| 勤務区分     | 勤怠管理     | 一回の勤怠が昼勤務か夜勤務かを表す区分。勤怠管理で記録された勤務区分は、時給管理でも適用する時給を選ぶ条件として同じ意味のまま利用する。                                                                                                                                             |
| 出勤         | 勤怠管理     | 勤務を開始した事実、およびその日時。                                                                                                                                                                                                                                                 |
| 退勤         | 勤怠管理     | 勤務を終了した事実、およびその日時。                                                                                                                                                                                                                                                 |
| 勤務状態     | 勤怠管理     | スタッフが現在どの勤務状況にあるかを表す区分。勤務中の勤怠がない「未勤務」、昼の勤務中勤怠がある「昼勤務中」、夜の勤務中勤怠がある「夜勤務中」を区別する。個々の勤怠の状態を表す「勤怠状態」とは別の概念として扱う。                                                                 |
| 勤怠状態     | 勤怠管理     | 個々の勤怠が現在どの状態にあるかを表す区分。出勤済みで退勤が未登録の「勤務中」、出勤日時と退勤日時が登録された「完了済み」、勤怠取消によって有効な勤怠として扱わない「取消済み」を区別する。退勤未登録という記録だけを根拠に、現実に現在も勤務中であると断定する意味では使用しない。 |
| 通常打刻     | 勤怠管理     | スタッフが、現在の勤務状態と矛盾しない形で実際の出勤または退勤を記録する操作。登録済み勤怠を事後に変更する「勤怠訂正」や、勤怠を無効にする「勤怠取消」とは区別する。                                                                                                                 |
| 未登録勤怠   | 勤怠管理     | 実際には勤務が行われたが、まだ勤怠記録として登録されていない勤務。管理者は、確認できた正しい出勤日時と退勤日時に基づいて新規作成する。未確認の日時を推測して補完する意味では使用しない。                                                                                             |
| 勤怠訂正     | 勤怠管理     | 登録済み勤怠の内容を、確認できた正しい内容へ変更すること。勤怠全体を無効にする「勤怠取消」とは区別し、訂正前後の変更経緯は勤怠変更履歴から追跡できる。                                                                                                                               |
| 勤怠取消     | 勤怠管理     | 登録済みの勤怠全体を、有効な勤怠として扱わない状態へ変更する不可逆な操作。物理削除ではなく、出勤だけ・退勤だけを対象とする部分取消や、取消後の復活も意味しない。                                                                                                                     |
| 勤怠変更履歴 | 勤怠管理     | 勤怠に対して行われた新規作成、勤怠訂正、勤怠取消などの変更経緯と操作者を追跡するための履歴。                                                                                                                                                                                         |
| 給与見込み   | 給与見込み   | 本システムに記録された勤務分数と設定済みの時給ルールから算出する月次の見込み額。税、社会保険、源泉徴収、法定割増、給与明細などを含む一般的な給与計算全般を意味しない。                                                                                                               |
| 時給         | 給与見込み   | 勤務時間に対して適用する一時間あたりの金額。                                                                                                                                                                                                                                         |
| 時給ルール   | 給与見込み   | 特定の利用者・勤務区分・日区分について、ある適用開始日以降に使用する時給を定めるルール。                                                                                                                                                                                             |
| 日区分       | 給与見込み   | 時給ルールを分類する曜日または祝日の区分。                                                                                                                                                                                                                                           |
| 適用開始日   | 給与見込み   | 時給ルールが有効になり始める日。対象の勤怠日に適用するルールを選ぶときの基準として使用する。                                                                                                                                                                                         |
| 時給改定     | 給与見込み   | 適用開始日を指定して新しい時給ルールを登録し、その日以降に適用される時給を変更すること。登録済みの時給ルール自体の内容を変更する訂正とは区別する。                                                                                                                                   |
| 時給履歴     | 給与見込み   | 対象利用者に登録されている時給ルールを、適用開始日ごとに確認するためのもの。勤怠変更履歴のような操作監査履歴ではなく、訂正前の値や削除済みルールを保持することも意味しない。                                                                                                         |
| 適用時給     | 給与見込み   | 対象となる勤怠の利用者、勤務区分、日区分、勤怠日に基づいて選択された時給。                                                                                                                                                                                                           |
| 時給未設定   | 給与見込み   | 対象となる勤怠日に適用できる時給ルールが存在しない状態。時給として 0 円が設定されている状態とは区別する。                                                                                                                                                                            |
| 不完全勤怠   | 給与見込み   | 給与見込みの算定に必要な勤務時間を確定できない勤怠。退勤日時が未登録である場合を含むが、不完全勤怠であることだけを根拠に現在も勤務中であると断定しない。                                                                                                                             |
| 算定上の不足 | 給与見込み   | 給与見込みを完全に算定できない原因となる情報不足。不完全勤怠や時給未設定などを区別して扱う。                                                                                                                                                                                         |
| 要確認       | 給与見込み   | 給与見込みの対象に算定上の不足があり、管理者による確認が必要であることを示す状態。個別の不足理由そのものを意味せず、理由は給与見込み詳細で確認する。                                                                                                                                 |
| 端数調整     | 給与見込み   | 勤怠ごとの表示額と、利用者・月単位で算出して丸めた給与見込み合計との間に生じる丸め差を表す表示上の調整額。                                                                                                                                                                           |

## 3. 用語の運用

- 一般的な技術用語ではなく、本システムの業務上の意味を共有する必要がある用語を対象とする。
- 新しい業務概念を導入するときは、既存の用語で表せないかを先に確認する。
- 区分の値は原則として独立した用語へ分けず、「利用状態」「勤怠状態」のような区分を表す用語の説明内で定義する。
- 同じ言葉を異なる意味で使う必要がある場合は、混同しない名称を優先し、必要な場合は分類ごとの意味を明示する。
- 「状態」のように単独では意味が曖昧な語は、必要に応じて「利用状態」「勤務状態」「勤怠状態」のように対象を明示する。
- 用語の意味を変更した場合は、要求・設計・UI・コードの名称との整合性も確認する。
