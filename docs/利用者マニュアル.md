# TimeCard 利用者マニュアル

## 1. 文書の役割

本書は、スタッフと管理者が TimeCard を利用するときの操作方法と、よくある状況への対応を説明する。

業務ルールや権限制約の正式な要求は [要件定義書](./要件定義書.md)、システム内部の実現方式は [設計書](./設計書.md) を参照する。アイコン、配置、余白などの細かな見た目は画面そのものを Source of Truth とし、本書では操作に必要な内容だけを扱う。

## 2. ログイン

TimeCard は LINE Login / LIFF を利用して本人確認する。

初めて本人確認に成功したスタッフは「承認待ち」となり、管理者が承認するまで勤怠機能を利用できない。承認後は再度認証することで利用を開始できる。

TimeCard 上の表示名は、初回登録後は LINE のプロフィール表示名とは独立した業務用名称として扱う。表示名を変更する場合は TimeCard 上で管理者が変更する。

利用停止中のスタッフは TimeCard を利用できない。再び利用中になった場合も、以前のログイン状態は再利用せず再認証する。

## 3. スタッフ向け操作

スタッフは主に次を行える。

- 当日の勤怠状態と現在勤務中の勤怠の確認
- 出勤・退勤
- 自身の月次勤怠履歴の確認

登録済みの勤怠はスタッフ自身では訂正・取消できない。修正が必要な場合は管理者へ依頼する。

### 3.1 出勤

1. 勤務区分（昼または夜）を確認する。
2. 実際の出勤時刻を入力する。
3. 出勤操作を実行する。

スタッフの通常打刻では日付を指定せず、入力した時刻を操作当日の日本時間の日付として扱う。

当日の出勤を打刻し忘れていて、まだ勤務中の勤怠が存在しない場合は、正しい当日時刻を入力して出勤できる。前日以前の出勤をスタッフ画面から追加することはできない。

すでに勤務中の場合は新しい出勤を開始できない。画面を開いてから勤怠状態が変わったなどの理由で操作が拒否された場合は、最新状態を確認してからやり直す。

### 3.2 退勤

勤務中の勤怠がある場合は、実際の退勤時刻を入力して退勤する。

当日の退勤を打刻し忘れていても、まだ勤務中であれば正しい当日時刻を入力して退勤できる。前日から実際に継続している勤務も、操作当日の正しい退勤時刻で通常退勤できる。

未勤務の状態から退勤することはできない。正しい退勤日時が分からない場合は推測して入力せず、管理者へ確認を依頼する。

### 3.3 勤怠履歴

履歴画面では、自身の勤怠を月単位で確認できる。

日を跨いだ勤務も、出勤した日を基準に所属月が決まる。翌日に退勤した勤怠は、勤務日を基準に 24 時間を超える時刻として表示されることがある。

同じ勤務日・同じ勤務区分に複数回勤務した場合も、それぞれ別の勤怠として確認できる。

### 3.4 打刻忘れや誤入力

当日中の単純な打刻忘れは、現在の勤務状態と矛盾しない場合に限り、正しい当日時刻を使った通常打刻で対応できる。

次の場合は管理者へ依頼する。

- 前日以前の打刻忘れ
- 登録済み勤怠の訂正・取消
- 現在の勤務状態と矛盾して通常打刻できない場合
- 正しい日時を確認する必要がある場合

確認できない日時を現在時刻などから推測して登録しない。

## 4. 管理者向け操作

管理画面では、主に「勤怠」「給与」「ユーザー」の各領域を利用する。

管理者は他の管理者を含む情報を閲覧できるが、勤怠・時給・表示名などの変更には対象者に応じた制限がある。基本的に、スタッフと管理者本人の情報は変更できる一方、他の管理者の情報は閲覧のみとなる。

### 4.1 ユーザー管理

ユーザー一覧からスタッフと管理者を確認し、対象ユーザーの詳細を開ける。

スタッフには次の利用状態がある。

- 承認待ち
- 利用中
- 利用停止

管理者はスタッフの表示名を変更でき、自分自身の表示名も変更できる。他の管理者の表示名は変更できない。

表示名は前後の空白を除いた 1〜100 文字で設定する。利用中・利用停止の利用者では、他の利用者と同じ表示名を使用できない。承認待ちのスタッフは表示名が未設定でも保持できるが、利用中へ変更する前に有効な表示名が必要となる。

スタッフの利用状態は次のように変更できる。

- 承認待ち → 利用中
- 利用中 → 利用停止
- 利用停止 → 利用中

利用停止にすると、そのスタッフの既存ログイン状態も利用できなくなる。再有効化後は再認証が必要となる。

管理者の利用状態は通常のユーザー管理画面から変更しない。

### 4.2 勤怠の確認

勤怠一覧では、利用者、期間、勤務区分、状態などを指定して勤怠を確認できる。

各勤怠の詳細では、現在の登録内容、変更履歴、操作者、適用時給、給与見込みまたは算出できない理由を確認できる。取消済みの勤怠も履歴として確認できるが、給与見込みには含まれない。

### 4.3 未登録勤怠の新規作成

出勤・退勤をともに打刻し忘れたなど、勤怠自体が登録されていない場合は、管理者が未登録勤怠を新規作成できる。

登録できる対象は、利用中または利用停止中のスタッフと、操作する管理者本人である。他の管理者や承認待ちのスタッフを対象にはできない。

1. 勤怠一覧から新規作成を開始する。
2. 対象者を選ぶ。
3. 勤務区分（昼または夜）を選ぶ。
4. 確認できた実際の出勤日時と退勤日時を入力する。
5. 内容を確認して作成する。

勤務日は出勤日時の日本時間の日付から決まる。退勤日時は出勤日時より後である必要があり、既存勤怠と勤務時間が重なる場合は作成できない。

正しい出勤日時・退勤日時を確認できない場合は推測して新規作成しない。

### 4.4 勤怠の訂正・取消

スタッフまたは管理者本人の勤怠について、管理者は権限の範囲内で訂正・取消できる。他の管理者の勤怠は閲覧のみで、訂正・取消できない。

訂正では、勤務区分、出勤日時、退勤日時を確認済みの正しい内容へ変更する。勤務中の勤怠について正しい退勤日時が確認できた場合は、退勤日時を補記して完了済みにできる。

勤怠そのものが誤登録だった場合は取消を行う。取消は勤怠全体を無効にする操作であり、取消後の復活・訂正・再取消はできない。

誤って早く退勤した場合は退勤だけを取り消して勤務中へ戻さず、実際の勤務終了後に確認できた正しい退勤日時へ訂正する。

競合エラーが表示された場合は、最新状態を確認してから操作し直す。

### 4.5 時給管理

ユーザー詳細から対象利用者の時給設定を確認できる。勤怠詳細から開いた場合は、その勤怠日時点で有効な時給を確認できる。

スタッフと操作する管理者本人については時給を変更できる。他の管理者の時給は閲覧のみとなる。

時給は、曜日または祝日と昼・夜の組み合わせごとに管理する。適用開始日を指定して複数の時給をまとめて改定でき、空欄は変更なし、0 円は有効な時給として扱う。

登録済みルールの訂正・削除は時給履歴から行う。既存ルールを訂正・削除すると、過去日時点の適用時給や給与見込みが変わる場合がある。

該当するルールがない場合は「未設定」となり、0 円の時給とは区別される。祝日は通常の曜日ルールより祝日ルールを優先する。

### 4.6 給与見込み

給与一覧では、対象月ごとに利用者別の給与見込みと、算定に不足があるかを確認できる。

給与見込みは、各勤怠の勤務時間と、その勤怠日に有効な時給ルールから算出する。

- 勤務時間を算出できない勤怠は給与見込みへ含めない。
- 勤務時間を算出できても時給が未設定の勤怠は給与見込みへ含めない。
- 算定できない勤怠がある場合は詳細で理由を確認する。
- 勤怠ごとの表示額と月次合計に丸め差がある場合は、その差額を確認できる。

給与詳細では対象月の勤怠を一件ずつ確認でき、対応する勤怠詳細から登録内容と計算根拠を確認できる。

TimeCard の給与見込みは、勤務分数と設定時給に基づく勤怠上の集計値である。税、社会保険、源泉徴収、法定割増、給与明細などを含む最終的な給与計算は行わない。

## 5. よくあるケース

### 打刻忘れに気づいた

- 当日の出勤忘れでまだ未勤務なら、正しい当日時刻で出勤する。
- 当日の退勤忘れでまだ勤務中なら、正しい当日時刻で退勤する。
- 前日以前の打刻忘れや登録済み勤怠の修正は管理者へ依頼する。
- 分からない日時は推測して入力しない。

### 出勤・退勤を両方打刻し忘れた

実際の出勤日時と退勤日時を確認できる場合は、管理者が未登録勤怠として新規作成する。正確な日時が分からない場合は作成しない。

### 過去の勤怠を修正したい

スタッフ本人は登録済み勤怠を変更できない。管理者が権限の範囲内で訂正または取消する。

### 操作したら競合エラーになった

同じ勤怠や時給設定が別の操作で先に更新されている可能性がある。最新状態を取得し、内容を確認してからやり直す。

### 新しく出勤しようとしたら勤務中エラーになった

同じ利用者が同時に複数の勤務中勤怠を持つことはできない。現在の勤務を正しい退勤時刻で終了してから新しい出勤を行う。退勤日時を確認できない場合は推測せず管理者へ確認する。

### 管理画面に入れない

再認証しても解決しない場合は、利用状態や管理権限をシステム運用者に確認する。
